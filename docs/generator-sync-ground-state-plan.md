# パターン生成 詳細設定追加 実装計画書（シンクロ生成・基底状態フィルタ）

## 概要

`generator.html` の詳細設定に以下の 2 つの設定を追加し、`siteswapGenerator.js` にロジックを実装する。

1. **シンクロサイトスワップの生成**: 生成結果をシンクロサイトスワップとして出力する
2. **基底状態フィルタ**: 基底状態のカスケード / ファウンテンから接続投げなしで直接入れるサイトスワップのみを生成する

## 設計方針

### API 設計

`SiteswapGenerator` の単体動作（依存関係なし）を維持する。既存呼び出しとの後方互換のため、
`create()` / `createRandom()` の末尾に `options` オブジェクトを追加する。

```js
SiteswapGenerator.create(ball, period, maxh, isSort, excNumL, isReverseOutput, {
    isSync: boolean,            // シンクロサイトスワップとして生成
    isGroundStateOnly: boolean  // 基底状態から直接入れるパターンのみ
});
```

### シンクロ生成の仕組み

アシンクロパターンを従来通り生成し、`siteswapLab.js` の `convertAsyncToSync()` と同一の規則で
シンクロ表記に変換する（`SiteswapGenerator` の独立性を保つため、変換ロジックはクラス内に自己完結で実装する）。

- 変換規則（`siteswapLab.js` / `siteswapProcessor.js` の `_syncToAsync` の逆変換と同一）
  - 偶数インデックス（右手）: 奇数値 `n` → `n-1` + クロス(`x`)
  - 奇数インデックス（左手）: 奇数値 `n` → `n+1` + クロス(`x`)
  - 偶数値はそのまま
- 奇数周期のパターンは 2 倍に繰り返してから変換する（`convertAsyncToSync` の `isRepeatNeeded` と同じ）
- この変換は `_syncToAsync`（検証側）の逆写像なので、変換結果は必ず有効なシンクロサイトスワップになる
  （すべて偶数値・ボール数保存・jugglable 維持）

**シンクロ変換とアシンクロの対応は全単射**（偶数長配列に対して）なので、アシンクロ段階の重複除去が
そのままシンクロ結果の重複除去になる。アシンクロの回転はシンクロでは「回転（偶数シフト）」または
「左右鏡像（奇数シフト）」に対応し、いずれも同一パターンとみなせるため追加の重複除去は不要。

### 短縮表記（`*`）

シンクロのペア列 `P[0..k-1]` について、`k` が偶数かつ後半が前半の左右入れ替え
（`P[j + k/2] == swap(P[j])`）である場合、前半のみ + `*` で表記できる
（`siteswapProcessor.js` の `_validateSyncPattern` の `*` 展開処理と正確に逆の関係）。

生成されたアシンクロパターンの回転はどれも同一パターンの表現なので、**短縮表記が可能になる回転を探索**し、
見つかればその回転の短縮表記で出力する。見つからなければ生成された回転をそのまま完全表記で出力する。
（例: アシンクロ `7445` → 回転探索により `(6x,4)*` を出力）

### 基底状態フィルタ

- **基底状態の定義**
  - アシンクロ: ボール数 `n` のサイトスワップ「n」（奇数=カスケード、偶数=ファウンテン、10 以上はアルファベット）
  - シンクロ: `details.html` → `SiteswapLab.calculateConnectionPattern('', pattern)` →
    `#preprocessConnectionPatterns` で補完される独自定義を採用
    - 偶数個: `(n,n)`
    - 奇数個: `(n+1x,n-1)(n-1,n+1x)`
- **判定方法**: 「基底状態から直接入れる」⟺「入力パターンの状態(state)が基底状態の状態と一致」
  ⟺「状態が `{0, 1, ..., n-1}` と一致」。
  状態計算は `siteswapLab.js` の `#calculateState()` と同一アルゴリズム
  （`maxHeight` ビート分を逆順に走査し、着地時刻 `num - (i+1) >= 0` を収集）で、
  判定は「すべての着地時刻が `n` 未満」で足りる
  （有効なサイトスワップでは状態の要素数は必ずボール数と一致し、要素は互いに異なるため）。
- **シンクロとの併用**: シンクロ変換は状態を変えない（変換前後で `_syncToAsync` により同じアシンクロ列に戻る）ため、
  アシンクロ段階の状態判定がそのまま使える。また状態が一致する場合の接続計算は iteration = 0（偶数）で
  完了するため、`#calculateConnection` のシンクロ用パリティ条件（iteration が偶数）も自動的に満たされる。
- **回転の正規化**: 基底状態かどうかは回転（開始位置）に依存する（例: `531` は基底状態だが `315` は違う）。
  生成された回転が基底状態でなくても、**基底状態になる回転が存在すればその回転で出力**し、
  どの回転も基底状態でなければ除外する。これにより出力された文字列は `details.html` で
  「直接入ることができます」と判定されるものに一致する。

### 重複除去と繰り返しパターン除外

- 既存の回転重複除去（`seenPatterns`）は維持。
- 周期未指定（1〜5 周期）時の「短い周期の繰り返し除外」（`#isRepetition`）は、従来の
  「生成後の結果文字列に対するフィルタ」から「`addPattern` 内でのアシンクロ文字列に対する判定」に移動する。
  シンクロ表記に変換後の文字列では繰り返し判定ができず、例えば周期 1 の「5」と周期 2 の「55」が
  どちらも `(4x,6x)` となり重複してしまうため。

### 効率化

- 基底状態判定・シンクロ変換は `addPattern`（重複除去通過後）でのみ実行し、探索木には影響させない。
  1 パターンあたり O(周期 × 最大高さ) 程度で、生成コストに対して無視できる。
- フィルタで除外されたパターンは `RESULT_MAX`（100,000 件）にカウントしない。
- 回転文字列の計算は 1 回にまとめ、重複チェックと `seenPatterns` 登録で共用する。
- 短縮表記の探索はペア数が奇数の場合は即座に打ち切る（回転しても不変のため）。

## 実装中の判断（ユーザーへの質問の代わりに採用した仕様）

1. **周期数・高さの上限・除きたい数値の意味（シンクロ時）**: いずれも変換前のアシンクロパターンに対して適用する。
   シンクロ表記では奇数値が ±1 されるため表示上の数値とは最大 1 ずれるが、入力パイプラインの一貫性を優先した。
   奇数周期を指定した場合、シンクロ出力は 2 倍の周期（ペア数 = 指定周期）になる。
2. **シンクロ時のボール数上限は 34**: 奇数値 35(z) は左手側で 36 になり表記不能（`z` が上限）のため、
   シンクロ生成ではボール数を 0〜34 に制限し、内部的な投げの最大値も 34 に制限する。
   これは `siteswapLab.js` のシンクロ基底状態補完の制限（1〜34 個）とも整合する。
3. **基底状態フィルタの出力回転**: 基底状態になる最初の回転（生成された回転から順に探索）で表示する。
   数値順ソートの見た目より「details.html でそのまま検証できる文字列」であることを優先した。
4. **シンクロ + 基底状態フィルタ併用時の短縮表記**: 基底状態になる回転の中から短縮表記が可能なものを優先して選ぶ。
   （短縮表記は文字列表現の圧縮であり展開結果は同一パターンなので、状態＝基底状態のまま変わらない）
5. **ランダム出力との併用**: `createRandom` は内部で `create` を呼ぶため、両オプションともそのまま適用される。

## 検証方法

- Node.js 上で `siteswapProcessor.js` + `siteswapLab.js` を読み込み、生成結果を突き合わせて検証する:
  1. **後方互換**: オプション未指定時の出力が従来版と完全一致すること
  2. **シンクロの有効性**: すべての出力が `SiteswapProcessor.validate()` で `isValid && isJugglable` になること
  3. **重複なし**: 出力に重複文字列がないこと（Set サイズ一致）
  4. **基底状態**: すべての出力が `SiteswapLab.calculateConnectionPattern('', p)` で
     `connection === '' && reverseConnection === ''`（= 直接入れる）になること
  5. **網羅性**: フィルタなし生成の各パターンについて、基底状態になる回転が存在するなら
     基底状態フィルタの出力にその回転が含まれること

## 検証結果

Node.js 上で `siteswapProcessor.js` + `siteswapLab.js` を正解系として突き合わせるテスト、および
ヘッドレスブラウザ（Chromium）での `generator.html` の実機確認を行い、すべて成功した。

### ロジック検証（Node.js）

1. **後方互換**: オプション未指定時の出力（5 パターンの引数組み合わせ）が旧バージョン（`origin/main` の
   `1.0.0`）と完全一致
2. **シンクロの有効性**: 生成された全パターンが `SiteswapProcessor.validate()` で
   `isValid && isJugglable`、`isAsync === false`、ボール数一致。件数はアシンクロ生成と一致（全単射の確認）
3. **重複なし**: すべてのケースで出力に重複なし。特に周期未指定時に「5」（周期1）と「55」（周期2）が
   同一シンクロ表記になる問題が発生しないことを確認
4. **基底状態**: 生成された全パターンが `SiteswapLab.calculateConnectionPattern('', p)` で
   `connection === '' && reverseConnection === ''`（直接入れる）
5. **網羅性**: フィルタなし生成の全パターンについて「基底状態になる回転が存在する ⟺ フィルタ結果に
   その回転が含まれる」ことを全数確認
6. **スポットチェック**:
   - 3 ボール周期 3 の基底状態 = `531` `522` `441` `423` `333`（既知の結果と一致。`450` `630` などの
     励起パターンは除外される）
   - 3 ボール周期 4 のシンクロにボックス `(4,2x)*` が短縮表記で含まれる
   - 周期 1 はシンクロで `(2x,4x)`（3 ボール）、`(4,4)`（4 ボール）になる
   - シンクロ生成でボール数 35 はエラー、高さ 35(z) を含むパターンは生成されない
7. **ランダム出力との併用**: 両オプション適用済みの結果から抽出されることを確認

  `(4x,2)(2,4x)` を表示し、基底状態フィルタ有効時の結果では接続が「(なし)」（直接入れる）になる
